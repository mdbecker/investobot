# Review changes conservatively

A DISPUTED_TO_VERIFIED label change with unchanged supporting citations requires
manual review. `supporting_evidence_status` distinguishes unchanged versus changed
citations; neither proves factual support. A renamed local source ID or a later
retrieval date cannot establish new evidence. Consult the cited source and provide
an exact updated fact locator before describing independent confirmation.

Choose an exact prior run and current run with `compare`, or inspect the selected
latest-two result from `changes`. Check returned baseline IDs and deterministic
ordering, including ties in research dates. Comparable company identity matters;
never mix similarly named issuers or silently reinterpret ticker changes.

Explain newly observed events separately from real-world occurrence dates.
Existing stable keys with new verified facts can be material updates. Added
sources supporting unchanged facts belong to corroborating evidence. Renamed
headlines, reordered arrays and editorial rewriting are not new developments.
Disputed assertions cannot be described as confirmed facts.

`reobserved_events` identifies a stable event returning after missing coverage.
Review its earlier last-observed run and current evidence, including any new
verified facts. It is not a new event. History searches stop at the selected old
baseline in research order; later observations must not inform an earlier delta.
Uncertain issuer identity or similar titles never justify merging event keys.

Review `disputed_claim_changes` separately from confirmed developments:
`DISPUTED_ADDED`, `DISPUTED_REVISED`, `DISPUTED_TO_VERIFIED`,
`VERIFIED_TO_DISPUTED` and `DISPUTED_NOT_REOBSERVED`. Inspect before/after
propositions, run IDs, source URLs and locators. A verified claim becoming
disputed withdraws confirmed-fact treatment; it does not prove falsity. An
unchanged disputed proposition with additional corroboration is evidence-only.
A dispute becoming verified can also appear in `updated_events`; category
counts overlap and must not be summed as distinct real-world developments.

Events absent from a later partial observation are `not_reobserved`; they are
not resolved, dismissed, disproven or retracted merely through silence. The same
rule applies to missing catalysts, hypotheses and follow-ups. Empty coverage is
not proof of no news. Retain unanswered prior questions when still relevant.
Effective context carries unresolved events, pending catalysts, unanswered
questions and tracked hypotheses through omitted runs, without automatic expiry.
Check each record's `last_observed_run_id`, `last_observed_as_of` and
`observation_status`. `NOT_REOBSERVED` is historical knowledge awaiting recheck;
an inherited thesis is `NOT_REASSESSED`. Only explicit sourced resolution,
retraction or supersession ends active carry-forward; full history remains.

For changed catalysts report before/after status and dates with cited evidence.
For changed thesis assessments show the unchanged hypothesis, old/new assessment,
rationale, related evidence and uncertainty. Changed statements under one thesis
ID are incompatible, not renames. Summarize limitations, nonoverlapping coverage,
unknown dates and ambiguous identities. Report no sentiment score, probability,
price prediction, ranking or automatic trading recommendation.

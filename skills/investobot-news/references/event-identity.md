# Stable evidence identities

An `event_key` identifies one underlying development across runs. Prefer a public
announcement, filing, case or document identifier, or a consistent manually
reviewed key grounded in original evidence. Headlines, dates and text similarity
alone cannot establish identity. Multiple outlets repeating one disclosure share
an event with several sources. Independent announcements remain separate even
when their titles match. Ambiguous continuity stays distinct with a warning.

Reuse a `fact_key` for the same checkable proposition; preserve its status and
exact source locator. New evidence for an unchanged proposition is corroboration,
not a new development. Cosmetic rewriting is not evidence of a changed fact.
Do not merge contradictions or promote disputed claims without resolving evidence.

Reuse `catalyst_id` for the same expected milestone and follow-up question IDs for
the same unresolved question. Dates and statuses require disclosed evidence;
an omitted catalyst is not automatically cancelled or completed.

Reuse `thesis_id` only with the same hypothesis statement. A rewritten hypothesis
requires a new identity; reusing an ID for a different statement makes comparison
incompatible. Assessments are research interpretations, never accepted decisions.

Keep event occurrence/announcement dates separate from source publication/access
dates. Previously occurring events first found now are newly observed, not newly
occurred. Unknown dates remain null with UNKNOWN certainty. The monitoring window
covers research publication/discovery and does not promise every event occurred
inside it. Upcoming catalysts can legitimately have future scheduled dates.
